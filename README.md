# MONOLITH

A self-hosted **AI agent workspace for small organizations**. Staff open one site, log in, and
**pick a mode** (Research, Code, Cowork, Agent) to put an agent to work on their files — all on
infrastructure you control, routed through one model gateway (cloud Claude/OpenAI/Gemini, or local
models via Ollama).

Assembled from open-source projects; built on the **MIT-licensed core of
[OpenWork](https://github.com/different-ai/openwork)**.

> **Status:** built and verified end-to-end on Docker. The engine is mid-migration onto the
> MONOLITH agent runtime in [engine/core/](engine/core/) — see
> [engine/core/packages/monolith/](engine/core/packages/monolith/) for the product delta and the
> deployment story that replaces the layout below.

---

## The two surfaces (one login)

| URL (local) | What it is |
|---|---|
| **http://localhost** | **The Hub** — launcher: a question box + mode tiles |
| **http://work.localhost** | The **workspace** (the agentic "do the work" engine) |

The Hub's **question box** and its **mode tiles** both open a workspace session pre-set to that
mode's agent, carrying the typed question into the composer:

| Mode | Opens |
|---|---|
| Research | `research` agent — multi-step research with a written, cited report |
| Code | `code` agent — read, write, refactor and run code |
| Cowork / Agent | default agent — general work on your files |

Modes are declared in [hub/modes.json](hub/modes.json) — edit that to add/rename tiles. Domain agents
live in [workspace-image/seed/.opencode/agent/](workspace-image/seed/.opencode/agent/).

## Quick start

```bash
cp .env.example .env          # or: scripts/new-instance.sh (generates secrets)
# add a provider key for good answers: ANTHROPIC_API_KEY= (best) or GEMINI_API_KEY=
docker compose up -d --build
docker compose exec ollama ollama pull qwen2.5:0.5b      # tiny test model; pull a bigger one for real use
```

- Open **http://localhost**, log in (`admin` / `Monolith-74967bd1` — change it below).
- Pick a mode. In the workspace, choose a model: **Claude / GPT / Gemini (cloud)** or **Qwen (local)**.

**Change the login:** `scripts/set-admin-password.sh admin '<new-pass>' && docker compose restart caddy`

**Get good answers:** the bundled local model is tiny. Put **one** key in `.env`
(`ANTHROPIC_API_KEY=` recommended), then `docker compose up -d --force-recreate litellm`.

## Multi-user (isolated workspaces)

```bash
scripts/add-user.sh alice 20 alicepass     # -> http://alice.localhost, own container+data+$20/mo budget
```

Each user gets their own container, volumes, login, and gateway budget key (isolation verified).

## Operations

| Script | Purpose |
|---|---|
| `scripts/new-instance.sh` | Fresh client instance with generated secrets |
| `scripts/add-user.sh <user> [budget] [pass]` | Isolated per-user workspace |
| `scripts/backup.sh` / `restore.sh` | Snapshot / restore all data (volumes) |
| `scripts/set-admin-password.sh <user> <pass>` | Change the login |

## Layout

```
docker-compose.yml     # the whole stack
hub/                   # the Hub launcher (index.html + modes.json), served by Caddy
webui/                 # builds & serves the OpenWork React UI (branded, ?agent= deep-link)
workspace-image/       # OpenWork workspace container: engine + agent tools + domain agents/skills
  seed/.opencode/agent # agent personas (chat/research/code)
litellm/config.yaml    # model aliases (cloud + local) + round-robin router
caddy/Caddyfile        # login, routing (hub / work), TLS, headers
caddy/users/           # per-user routes (generated by add-user.sh)
openwork/              # upstream reference clone (webui builds the UI from here)
```

## Notes / production follow-ups
- **One password, per-host prompt:** login is HTTP Basic, so browsers prompt once per host
  (hub / work) per session. True no-reprompt **SSO = an Authelia upgrade** (documented next step).
- **Model quality** depends on a real key in `.env` (local Qwen is weak).
- **Modes** are tuned personas in [workspace-image/seed/.opencode/agent/](workspace-image/seed/.opencode/agent/).
- Deep visual rebrand of the OpenWork UI (beyond the product name) is a later, careful task.

## Cowork-style UI (2026-07)

The UI is a MONOLITH-branded, Claude-Cowork-style workspace built from the tracked
`openwork/apps/app` source (MIT core): Chat|Cowork|Code mode tabs (mapped to seeded agents),
task home with starter cards, task rail (Progress/Artifacts/Context), Projects (workspaces with
an AGENTS.md instructions editor), Scheduled tasks, a persistent Dispatch thread per workspace,
Customize hub, and an Admin panel.

**monolith-server/** is the product sidecar (dependency-free Node) powering Scheduled, Dispatch,
and org config under `/__monolith/*`:
- Native path: embedded in `native/serve-ui.mjs`; state in `native/data/`.
- Docker path: `monolith-server` compose service; Caddy routes `work.<domain>/__monolith/*`
  to it behind the site login; state in the `monolith_sidecar` volume.

Rebuild the UI after changing `openwork/apps/app`:
`pnpm -C openwork --filter @openwork/app typecheck && node native/build-ui.mjs`
(native) and `docker compose build webui && docker compose up -d webui` (Docker).
